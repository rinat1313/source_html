# Анализ: интеграция со сбором данных ЕИС

Документ обобщает выводы по `HUMAN_EIS_OVERVIEW.md` и `AGENT_EIS_INTEGRATION.md` для проектирования сервиса сбора размещённых сведений.

---

## 1. Цель и границы

**Цель:** забирать уже размещённые XML (извещения, протоколы, контракты/договоры, планы, НСИ), валидировать по XSD, нормализовать и сохранять с дозапросом по номеру / периоду / региону / GUID.

**Вне границ сервиса сбора:**

| Контур | Почему вне |
|---|---|
| ГИС НР / JWT / ЭМ | События ЭТП, не реестр закупок |
| AS2 / upload / IncomingWebService | Приём в ЕИС, не чтение |
| Парсинг HTML сайта zakupki.gov.ru | Нестабильно; официальный путь — XML/SOAP/FTP/REST |
| ГОСТ Р 34.10-2001 | Запрещён; нужны актуальные КЭП |

---

## 2. Два независимых контура

| | **44-ФЗ** | **223-ФЗ** |
|---|---|---|
| Главный API | SOAP getDocs* + WSDL реестров | HTTPS multipart REST `/223/integration/...` |
| Bulk | Региональные / rule FTP-выгрузки (`fcsExport.xsd`) | FTP-выгрузки (§2.4); НСИ с FTP **с 01.01.2025 отключены** |
| Ключ идемпотентности | `regNumber` + тип + версия/дата | `guid` (+ version / registrationNumber) |
| XSD | `fcsExport`, `IntegrationTypes`, GetDocsWS | `purchase.xsd`, `contract.xsd`, `Types.xsd`, … |

**Вывод:** парсеры, клиенты и конфиг `law=44|223` должны быть раздельными. Смешивать схемы в одном парсере нельзя.

---

## 3. Домены и auth

| Домен | Когда |
|---|---|
| `int.zakupki.gov.ru` | Односторонняя TLS, getDocsOrg/IP, часть 223 REST |
| `int44-ttls-cert.zakupki.gov.ru` | Mutual TLS (ГОСТ + клиентский сертификат): getDocsMis/Ris/LE, очереди |
| `int44` / `int223` | Legacy; не хардкодить как единственный endpoint |

WSDL в комплекте 44 ещё содержат старые хосты — в коде выбирать домен по типу TLS, а не копировать из WSDL «как есть».

Без регистрации у Оператора ЕИС, кода ИС и прав в ППА полноценный API недоступен.

---

## 4. Рекомендуемые каналы сбора

| Приоритет | Канал | Сценарий |
|---|---|---|
| 1 | getDocsMis (SOAP) | Широкий публичный сбор 44 (+ selectionParams223) при наличии mTLS |
| 2 | Региональная / rule-выгрузка | Массовая история и ежедневная дельта |
| 3 | REST 223 publishedInfo / nsi | Точечный и периодный сбор 223 |
| 4 | Очередь РИС (`getObject` + `ack`) | Непубличные документы по подписке |
| 5 | SOAP реестров (РК, РПГ, РНП…) | Список/карточка по запросу |

Типовой async-поток getDocs: запрос → `archiveUrl` / `noData` → при необходимости poll `getPreparedPart` → GET архива → unzip → XML.

---

## 5. Ограничения и риски

| Риск / лимит | Влияние |
|---|---|
| До 1000 организаций в одном getDocs | Нужна нарезка запросов |
| Архивы по ссылке с отложенной готовностью | Обязателен poll + retry/backoff |
| Нет права хотя бы на одну организацию из списка | Ошибка на весь запрос |
| Несовпадение `sender` и сертификата | Отказ |
| НСИ 223 только через сервисы | Не ждать FTP после 01.01.2025 |
| Часовой пояс заказчика в датах | Не интерпретировать `Z` как UTC без контекста |
| Устаревшие разделы альбома | Сверять статус выгрузок с текущей ред. 2.9 |

## 6. Архитектурные выводы

```
scheduler
  → collectors_44 | collectors_223
      → raw (zip/xml)
          → validate (XSD по law)
              → parse → upsert (ключ по law)
                  → checkpoint
```

Обязательные компоненты:

1. Выбор домена по auth-профилю.
2. Хранение raw + идемпотентный upsert.
3. Checkpoint по (region/documentType/period) или аналог для 223.
4. Секреты и ключи вне репозитория и логов.
5. Конфиг `law`: `44` / `223` / `both`.

---

## 7. MVP (рекомендация анализа)

**Предпочтительно A — 44 getDocsMis + mTLS:**

1. SOAP из `WebServiceGetDocsMis.wsdl`.
2. `getPublicDocsByOrgRegion` + `getNsi` (selectionParams44).
3. Скачивание архивов, парсинг извещений / контрактов / процедур.
4. Checkpoint и raw-store.

**Альтернатива B — 223 REST**, если доступ только к контуру 223.

**Вариант C — оба закона** с общим raw-store и раздельными парсерами.

Практичный порядок наращивания: доступ → 2–3 типа документов + один НСИ → ежедневная дельта → расширение типов → при необходимости 223 и скрытые документы.
