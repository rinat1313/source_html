# Инструкция работы с ЕИС

Пошаговый порядок для команды: от доступа до эксплуатации сервиса сбора.

---

## Этап 0. Подготовка решений

1. Выбрать закон: **только 44**, **только 223** или **оба**.
2. Определить роль ИС: ФОИВ/MIS, РИС, организация/ЮЛ/ИП, ВСРЗ, КИС/РМИС.
3. Составить список сущностей (пример для 44: извещения ЭА/ЭОК, протоколы, контракты, НСИ ОКПД2).
4. Назначить ответственного за сертификаты и код ИС (секреты не в git и не в чат).

Критерий готовности: зафиксированы `law`, профиль auth, перечень documentType / entityType.

---

## Этап 1. Доступ у Оператора ЕИС

1. Зарегистрировать ИС в перечне информационных систем.
2. Получить код ИС (`sender` / `systemIdentifier` по профилю).
3. Оформить КЭП (не ГОСТ Р 34.10-2001); для MIS — mutual TLS, часто УЦ Федерального казначейства.
4. Выдать права в ППА на нужные `subsystemType`, организации, регионы, реестры.
5. Проверить, какой домен нужен:
   - односторонняя TLS → `int.zakupki.gov.ru`;
   - двусторонняя TLS → `int44-ttls-cert.zakupki.gov.ru`.

Критерий готовности: успешный тестовый вызов (getDocs или REST) в TEST/PROD по профилю.

---

## Этап 2. Материалы разработчика

1. Держать под рукой альбомы и схемы нужной версии (см. README этой папки).
2. AI/backend отдать файл `AGENT_EIS_INTEGRATION.md`.
3. Человеку/заказчику — `HUMAN_EIS_OVERVIEW.md` и этот файл.
4. При конфликтах имён папок после распаковки ориентироваться по содержимому:
   - 44: `fcsExport.xsd`, `GetDocsWS`, «ЕИС. Альбом ТФФ», Приложения 1–18;
   - 223: PDF требований, `Интеграционные схемы 223-ФЗ 16.2/`.

---

## Этап 3. Реализация MVP

### Вариант A (44-ФЗ, рекомендуется при getDocsMis)

1. Подключить SOAP-клиент из WSDL getDocsMis.
2. Реализовать `getPublicDocsByOrgRegion` и `getNsi`.
3. Обработать async: `noData` / `archiveUrl` / poll `getPreparedPart`.
4. Скачать ZIP по тому же TLS-профилю, распаковать, валидировать по `fcsExport.xsd`.
5. Парсить выбранные корни; upsert по `regNumber` + тип + версия.
6. Сохранять checkpoint (region, documentType, period) и raw.

### Вариант B (223-ФЗ)

1. REST multipart `publishedInfo` + `/nsi` (version 1.3).
2. Декодировать zip/base64; валидировать XSD 223.
3. Upsert по `guid`.
4. НСИ только через сервис, не через FTP.

### Общие правила кода

- Не смешивать XSD 44 и 223 без явного `law`.
- Не хардкодить только legacy-хосты из WSDL.
- Не логировать пароли, ЭП, клиентские ключи.
- Не реализовывать upload/AS2, если задача — только сбор.

---

## Этап 4. Расписание и дозабор

1. Настроить scheduler: ежедневная дельта по периоду или rule-выгрузке.
2. Добавить дозабор по реестровому номеру / GUID / списку заказчиков.
3. Нарезать запросы getDocs пачками до 1000 организаций.
4. Retry с backoff на подготовку архивов и сетевые сбои.
5. Мониторить статусы прогонов: успех, `noData`, ошибки прав, таймауты подготовки.

---

## Этап 5. Расширение

1. Добавлять типы документов по приложениям альбома (3, 4, 14 для 44; entityType для 223).
2. При необходимости — очередь РИС для непубличных документов (`getObject` + обязательный `ack`).
3. Подключить второй закон только после стабильного MVP первого.
4. SOAP-реестры (РК, РПГ, РНП…) — по отдельной потребности «список/карточка».

---

## Этап 6. Эксплуатация (без ручного SOAP/REST)

Оператор сервиса:

1. Выбирает закон и типы документов.
2. Задаёт регионы или список заказчиков.
3. Включает расписание.
4. Смотрит статусы прогонов.
5. Ищет у себя по реестровому номеру / дате / ИНН / GUID.

Ручной вызов SOAP и REST не требуется — это внутри сервиса.

## Куда смотреть при ошибках

| Симптом | Куда |
|---|---|
| Отказ TLS / сертификат | Альбом 44 §2.18–2.19; домен `int` vs `int44-ttls-cert` |
| Ошибка прав / sender | ППА, код ИС, список организаций ≤ 1000 |
| Пустой ответ | `noData`; сузить период/тип; проверить права на организации |
| Архив не готов | `getPreparedPart`, увеличить timeout/poll |
| Ошибка парсинга | Версия XSD vs версия альбома; `what is new.txt` |
| 223 НСИ | Только REST `/nsi` или getDocs; FTP отключён с 2025 |
| Коды ошибок getDocs | Приложение 1, раздел 9 альбома 44 |

Детали API — в `AGENT_EIS_INTEGRATION.md`. Обзор для человека — в `HUMAN_EIS_OVERVIEW.md`. Анализ границ — в `ANALYSIS.md`.
