Регламент формирования сообщений с вложениями
При формировании сообщений с вложениями в элемент UID записывается уникальный идентификатор файла вложения. Прямая ссылка на файл получается путем подстановки UID в шаблон URL с указанным templateId. Шаблоны URL указываются в настройках ГИС НР для каждой Электронной площадки/ЕИС.
Для каждого шаблона указывается templateId (строковое значение), однозначно идентифицирующее шаблон в рамках данной Электронной площадки/ЕИС.
Для каждой Электронной площадки/ЕИС один шаблон является шаблоном по умолчанию. Шаблон URL представляет собой строку, содержащую элемент [UID] (например, http://aaa-bbb.ru/[UID]). При необходимости загрузки файла ГИС НР обрабатывает шаблон URL, подставляя UID файла в шаблон вместо [UID].
Скачивание файла выполняется по протоколу HTTPS без авторизации.

Ниже приведены возможные варианты направления вложений площадками/ЕИС:
Вариант 1 — всегда передавать полный URL на вложение
Шаблон: [in]
UID: http://etp.ru/attach?id=3738282
В этом варианте площадка/ЕИС делает один «пустой» шаблон (он будет шаблоном по умолчанию). Для формирования целевого URLа, на стороне НР UID подставляется в шаблон. При этом при передаче вложения templateId не передается (т.к. один шаблон и он по умолчанию). Т.к. шаблон пустой, то целевой URL будет совпадать с UID.
Вариант 2 — в шаблон вынести постоянную часть URL и передавать только GUID (или ID)
Шаблон: http://new-etp.ru/attach?guid=[in]
UID: 239d329d-d32923d832-23dhudh3-23932d
В этом варианте (если один шаблон) в каждом вложении будет передаваться GUID, при этом templateId передавать не обязательно, т.к. шаблон один. При подстановке UID в шаблон будет получаться целевой URL.
Вариант 3 — сделать несколько шаблонов
Предусматривается возможность использовать несколько шаблонов, один из которых будет основным (шаблон по умолчанию). В этом случае при передаче вложения нужно указать templateId, если шаблон отличается от шаблона по умолчанию.

mimeType | Н | T | Mime-тип вложения | Допустимые значения приведены ниже (Таблица 1).
signatureType | О | Т | Тип подписи | 0 — присоединенная  1 — отсоединенная 2 — хеш от файла вложения по алгоритму ГОСТ Р 34.11-2012 3 — хеш от файла вложения по алгоритму ГОСТ Р 34.11-94 4 — хеш от файла вложения по алгоритму SHA-256
signature | Н | base64Binary | Подпись | Отсоединенная подпись или хеш.  Хеш передавать в формате HEX. Отсоединенную подпись передавать в кодировке Base64 (without newline).
